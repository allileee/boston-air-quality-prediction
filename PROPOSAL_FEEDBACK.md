# Project Proposal Feedback

The project is clearly described and well motivated, and the goal of predicting tomorrow's AQI as both a classification (below or above 50) and a regression is specific and easy to follow. The feature list is thorough, and including lagged pollution levels and seasonality is a good choice. To strengthen the proposal, please state how you will measure success, such as the metrics for each task (for example F1 and ROC-AUC for classification, RMSE or MAE for regression) and a simple baseline to beat, like a persistence model that predicts tomorrow's AQI as today's. Since AQI is usually below 50 on most days in Boston, also say how you will handle class imbalance. The data collection plan names Open-Meteo and the EPA AQS API, but the sources are not linked, and it does not say which years or which monitoring stations you will use, so please specify these. Note that the goals say "based on today's weather conditions," while the features also include pollutant levels, so clarify this wording. The timeline is reasonable, but it says "weather monitors" in week 1 where you likely mean air quality monitors, and it does not mention a chronological train/test split or time-based validation to prevent leakage, which matters a lot for time series data. Finally, consider describing how you will handle missing days and monitor outages, and proofread for small wording issues.
